How to run QA Copilot locally

Step-by-step setup on Windows: Python venv, Groq API, backend API, React UI, data paths, and reindex.

API :8843 UI :5173 Python 3.11–3.13 only
KT home Run locally RAG architecture & explorer

Step 0 Prerequisites

RequirementNotes
Python 3.11, 3.12, or 3.13 Do not use Python 3.14 for this project — qdrant-client / protobuf fail with Metaclasses with custom tp_new.
Node.js + npm For the React + Vite UI (frontend/).
Groq API key Create one at console.groq.com and put it in .env.
Disk space First run downloads BGE-M3 and reranker models (several GB).
Ports: This project uses 8843 for the API (not 8000 or 8500, which you may already use for other apps). The dev UI uses 5173.

Step 1 First-time setup (once per machine)

Open PowerShell and go to the project folder:

cd "D:\manjusha\AITester2xBlueprint\QACopilot\QACopilot"

Create a Python 3.11 virtual environment and install dependencies:

py -3.11 -m venv .venv
.\.venv\Scripts\activate
python -m pip install --upgrade pip
pip install -r requirements.txt

Copy environment template and add your Groq key:

copy .env.example .env
notepad .env

Set at minimum:

GROQ_API_KEY=your_key_here

Data paths in .env

The backend reads these names (not the old COPILOT_PATH_* names):

Optional: change API port if 8843 is busy:

QACOPILOT_API_PORT=8843

Step 2 Start the API (terminal 1)

Always use the venv Python — not system python if that is 3.14.

cd "D:\manjusha\AITester2xBlueprint\QACopilot\QACopilot"
.\.venv\Scripts\activate
python app.py

Or use the helper script:

.\start.ps1
When it works you should see: Uvicorn running on http://0.0.0.0:8843

Verify API

URLPurpose
http://127.0.0.1:8843/api/healthCollection chunk counts
http://127.0.0.1:8843/docsSwagger API docs
http://127.0.0.1:8843/kt/These KT HTML pages

Step 3 Start the UI (terminal 2)

Leave the API running. Open a second PowerShell window:

cd "D:\manjusha\AITester2xBlueprint\QACopilot\QACopilot"
.\start-ui.ps1

Or: cd frontend then npm install and npm run dev.

Open the app:

http://localhost:5173/

Vite proxies /api to http://127.0.0.1:8843. If you changed the API port, create frontend/.env:

VITE_API_PROXY=http://127.0.0.1:YOUR_PORT

Step 4 Wizard, paths, and reindex

  1. Open http://localhost:5173/ → Status → set data paths and save (local_paths.json).
  2. Confirm folders exist: data/PDF, data/MD, data/CSV/testcases_vwo_100.csv, and cloned repos under data/repos/.
  3. Click Reindex all in the co-pilot UI (or call POST /api/ingest/all from Swagger).
  4. First reindex is slow (model load + embedding). Check /api/health — counts should be > 0.
  5. Ask a question in the co-pilot view, or use the RAG explorer to debug retrieval.

Troubleshooting

Metaclasses / protobuf error on python app.py

You are on Python 3.14. Use .\.venv\Scripts\python.exe app.py or activate .venv first.

127.0.0.1:5173 — connection refused

The Vite dev server is not running. Run npm run dev in frontend/ (terminal 2).

UI cannot reach API / wizard errors

Ensure terminal 1 still has the API on port 8843. Test /api/health in the browser.

PDF / CSV not indexed

Check .env uses PDFS_DIR and TESTCASES_CSV (not commented COPILOT_PATH_*). Restart API after editing .env, then reindex.

All collection counts are 0

Run Reindex all after paths are set. Ensure files exist at the paths in /api/meta or the wizard.
